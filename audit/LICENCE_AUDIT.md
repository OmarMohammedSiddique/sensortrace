# Licence and provenance audit

Audit date 2026-11-12, baseline commit `651b83e`. Inventory: [`SBOM.json`](SBOM.json), generated by
`scripts/generate_sbom.py` from the resolved lock files and installed package metadata.

This is engineering due diligence, not legal advice. Items marked **Legal review** need a lawyer before
commercial distribution.

## Result

| Question | Finding | Evidence |
|---|---|---|
| Any GPL or AGPL component? | **None** in 871 components (runtime or development) | Licence fields in `SBOM.json`; search for `GPL` returns only LGPL entries |
| Any non-commercial component? | **None** installed | Same search; the non-commercial Binghamton toolbox and `bm3d` were never added |
| Third-party source code copied into the repository? | **None found** | 302 tracked files, all first-party; no vendored directories; the reference implementation is fetched to an ignored directory by script |
| Dataset images redistributed? | **No** | Tracked images are 11 synthetic test fixtures and one results plot; `data/` is git-ignored |
| Does the project state its own licence? | **No**. All rights reserved by default | No `LICENSE` file. **Open** |
| Are third-party notices shipped with the container images? | **No** | No notices file. **Open**, see obligations |

## Components that carry obligations

|---|---|---|---|---|
| psycopg, psycopg-binary | LGPL-3.0-only | Imported unmodified by the backend; the binary wheel bundles libpq | Keep the notice and licence; let recipients replace the library (satisfied by shipping it as a separate, unmodified Python package); provide its source or a link on request | Low. **Legal review** of the LGPL checklist for shipped images |
| sharp and `@img/sharp-libvips-*` | Apache-2.0 and LGPL-3.0-or-later | Pulled in by Next.js for image optimisation. The application does not use `next/image` (0 imports), but the binaries are present in `node_modules` and the web image | Same as above | Low. Could be removed from the image to avoid the question |
| OpenCV wheel (bundled FFmpeg) | Apache-2.0; FFmpeg under LGPL-2.1 inside the wheel | Only `imdecode`, `resize`, `cvtColor`, `Laplacian` are called; no video code | Keep notices; do not prevent replacement | Low. Not visible in package metadata, known from the upstream README. **Legal review** |
| NumPy, SciPy wheels | BSD-3-Clause; bundle OpenBLAS (BSD) and GCC runtime libraries (GPL with runtime library exception) | Numerical core | Keep the wheels' licence files | Low: the runtime exception permits this use |
| certifi | MPL-2.0 | CA bundle (data), unmodified, transitive | Keep notice; publish changes to MPL files if modified (they are not) | Low |

| Geist typeface | SIL OFL 1.1 | Self-hosted fonts | Keep the licence with the font files; do not sell the font alone | Low |
| Redis server image | RSALv2 or SSPLv1 (7.4+) | Unmodified separate service in Compose | Do not offer Redis itself as a managed service | Low for this use. Valkey (BSD) is a drop-in alternative. The Vercel deployment uses Upstash under its own terms |

| email-validator | Unlicense (public domain dedication) | Runtime | None | Some organisations do not accept the Unlicense. **Legal review** if that applies |

## Hosted services (Vercel deployment)

Vercel, Neon and Upstash are used under their own service terms, accepted by the account owner. The
`@vercel/analytics` and `@vercel/speed-insights` packages and the `vercel` Python SDK are MIT or
Apache-2.0 (see SBOM).
